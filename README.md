# ExitKit AI 🧳

**Open-source AI-агент для передачи дел увольняющегося сотрудника.** Из разрозненных заметок формирует редактируемые задачи, незакрытые вопросы, контакты, чек-лист и PDF-пакет для преемника.

## Возможности MVP

- 📥 Ввод текста и загрузка `.txt`, `.md`, `.pdf`, `.docx`.
- 🤖 Анализ локальной LLM (Ollama) через OpenAI-compatible API.
- 🧩 Структурирование задач: название, статус, приоритет, ответственный, срок, следующие шаги, блокеры, цитата из источника.
- 📝 Редактирование любых полей в браузере до экспорта.
- 📄 Экспорт PDF с кириллицей и JSON.
- 🔐 Документы обрабатываются в оперативной памяти; сервер не записывает содержимое файлов в БД.

## Быстрый старт

**Требования:** Python 3.11+, Ollama, шрифт DejaVu Sans для PDF.

```bash
# В отдельном терминале установите/запустите Ollama и скачайте модель
ollama pull qwen2.5:7b
ollama serve

# В терминале проекта
python -m venv .venv
source .venv/bin/activate    # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Откройте **http://localhost:8000**.

На Ubuntu/Debian для кириллицы в PDF при необходимости: `sudo apt-get install fonts-dejavu-core`.

Ollama по умолчанию: `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=qwen2.5:7b`, `LLM_API_KEY=ollama`.

Для OpenAI-compatible провайдера укажите переменные окружения, например:

```bash
export LLM_BASE_URL="https://your-provider.example/v1"
export LLM_MODEL="your-model"
export LLM_API_KEY="your-api-key"
uvicorn app.main:app
```

⚠️ При подключении удалённого провайдера содержимое заметок отправляется провайдеру. Не отправляйте конфиденциальные данные без разрешения организации.

## Как работает агент

`Файлы/заметки → извлечение текста → LLM → проверка JSON по Pydantic → редактируемые карточки → PDF/JSON`

Основной агент: `app/agent.py`. HTTP API и экспорт: `app/main.py`. Интерфейс: `static/index.html`.

### API

- `GET /api/health` — проверка запуска.
- `POST /api/generate` — `multipart/form-data`, поля `notes` и необязательные `files` (многократно).
- `POST /api/export/pdf` — JSON объекта handover, ответ `application/pdf`.
- `GET /docs` — интерактивная OpenAPI-документация.

## Пример результата

Смотрите `examples/handover.json`. Агент **не должен выдумывать** ответственных и дедлайны: неизвестные сведения оставляет неизвестными, источник задачи показывает отдельно.

## Ограничения текущего MVP

- PDF должен содержать текстовый слой. OCR для сканов пока нет.
- Большие файлы и контекст модели ограничены (5 МБ/файл, 80 000 символов суммарно; контекстный лимит самой модели может быть меньше).
- Нет авторизации, многоарендности, истории версий, интеграций с Jira/Notion/Slack, автоматической проверки фактов и разграничения доступа.
- Не размещайте без доработок в открытом интернете: нужны аутентификация, rate limiting, аудит, сканирование вложений, политики хранения, контроль PII/секретов и проверка безопасности.
- LLM может ошибаться; финальный пакет должен утверждать ответственный сотрудник.

## Roadmap

1. Approval-flow: уходящий сотрудник → менеджер → преемник.
2. Агент проверки полноты: уточняющие вопросы и оценки уверенности с подтверждением источников.
3. Интеграции Jira, Linear, Notion, Google Drive, Confluence.
4. On-prem установка, роли, аудит, redaction PII и хранение с шифрованием.
5. Набор тестов на галлюцинации, prompt injection и качество handover.
